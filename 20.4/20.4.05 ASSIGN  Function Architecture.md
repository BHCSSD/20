> [!NOTE]
> **How to Write Correct Python Asserts**
> In Python, `assert` is a keyword, not a function. You evaluate an expression to see if it results in `True`. If it does, nothing happens, and your program keeps running. If it evaluates to `False`, your program instantly crashes with an `AssertionError`.
> * **Correct Syntax (No Outer Parentheses):** `assert balance == 100`
> * **Why parentheses hurt:** Writing `assert(x == y)` works fine for simple checks, but if you accidentally type a typo like `assert (x == y, "Error")`, Python interprets this as a non-empty tuple. In Python, non-empty tuples always evaluate to `True`, meaning your test will **pass even if your code is completely broken**! Stick to standard keyword spacing.

## Part 3: Robust Input Validation (Loop Exercises)

### Exercise 3.1: The Age Trap

Write a function named `get_valid_age`.

* Inside, use a `while` loop to continuously prompt the user with `input("Enter your age: ")`.
* Use `.isdigit()` to check the input.
* If the user enters letters or symbols, print `"Error: Age must be a positive integer."` and loop again.
* Once they enter a valid numeric string, convert it to an integer and **return** it.
* *Note: Because this function relies on interactive user `input()`, you do not need to write automated assert statements for this Exercise.*

> [!NOTE]
> **Choosing a Python numeric string check:**
> - **`.isdecimal()`** Strict `0-9` digits only. **Safest before `int(s)`** (rejects `"²"` and `"½"`).
> - **`.isdigit()`**  standard digits plus superscripts/subscripts (`"²"`).
> - **`.isnumeric()`** Broadest check; includes fractions (`"½"`), Roman numerals (`"Ⅷ"`), and CJK numbers (`"四"`).
> - **Floats & negatives (`"-5"`, `"3.14"`)**  All three return `False`; wrap `float(s)` in a `try/except ValueError` block instead.
